# Cryptographic Hash & Key Derivation Utility

![Python](https://img.shields.io/badge/Python-3.9%2B-blue)
![Cryptography](https://img.shields.io/badge/Cryptography-SHA256%20%7C%20SHA512-green)

![License](https://img.shields.io/badge/License-MIT-yellow)

A Python command-line utility for SHA-256/SHA-512 hashing, PBKDF2-HMAC-SHA256
key derivation, HMAC message verification, and file checksum comparison.

## Project Overview

This project demonstrates common cryptographic building blocks through a
small CLI. It supports hashing UTF-8 strings and files, deriving keys from
passwords using PBKDF2 and a salt, authenticating messages with HMAC, and
comparing file checksums.

### Features

- SHA-256 and SHA-512 string hashing.
- SHA-256 and SHA-512 file hashing using chunked reads.
- PBKDF2-HMAC-SHA256 key derivation with configurable iterations and length.
- Cryptographically random 16-byte salt generation when no salt is supplied.
- HMAC-SHA256 generation through the Python API and CLI verification.
- File checksum comparison.
- Unit tests with published known-answer vectors.

## Usage Examples

### Show help

```bash
python crypto_utility.py --help
```

### Hash a string with SHA-256

```bash
python crypto_utility.py hash-string "Hello World"
```

### Hash a string with SHA-512

```bash
python crypto_utility.py hash-string "Hello World" --algorithm sha512
```

### Hash a file

```bash
python crypto_utility.py hash-file sample.txt --algorithm sha256
```

For SHA-512:

```bash
python crypto_utility.py hash-file sample.txt --algorithm sha512
```

### Derive a key with PBKDF2

```bash
python crypto_utility.py derive-key --iterations 600000 --length 32
```

The program prompts for the password rather than accepting it as a command-line
argument. A random salt is generated by default. To reuse a previously stored
salt (hexadecimal, at least 16 bytes):

```bash
python crypto_utility.py derive-key --iterations 600000 --length 32 --salt YOUR_32_OR_MORE_HEX_CHAR_SALT
```

Store the salt and parameters with the protected data so the same key can be
derived later. The salt is not secret.

### Verify an HMAC-SHA256 tag

```bash
python crypto_utility.py hmac-verify "Hello" --key-hex YOUR_KEY_HEX --expected YOUR_HMAC_HEX
```

A successful check prints `HMAC verification: SUCCESS`. A mismatch returns a
non-zero exit status.

### Compare a file checksum

```bash
python crypto_utility.py compare-checksum sample.txt EXPECTED_SHA256
```

Use SHA-512 when appropriate:

```bash
python crypto_utility.py compare-checksum sample.txt EXPECTED_SHA512 --algorithm sha512
```

## Cryptographic Security Explanation

### SHA-256 and SHA-512

SHA-256 and SHA-512 are members of the SHA-2 family. They map input data of
arbitrary length to fixed-size digests of 256 and 512 bits respectively.
They are useful for integrity checks and as components in larger protocols.
They are not encryption algorithms and cannot be reversed to recover input.

### PBKDF2

PBKDF2 is a password-based key derivation function. This project uses
PBKDF2-HMAC-SHA256 with a configurable iteration count, output length, and
salt. A unique random salt helps ensure that identical passwords do not
produce identical derived keys. The CLI defaults to 600,000 iterations and
requires at least 100,000 iterations. Benchmark settings for the target
environment and review current security guidance before deployment.

### HMAC

HMAC combines a secret key with a hash function to produce a message
authentication code. This project uses HMAC-SHA256. Verification uses
`hmac.compare_digest()` to avoid ordinary content-dependent string
comparison. HMAC provides integrity and message authentication, not
confidentiality or encryption.

### File checksums

A checksum comparison checks whether a file's calculated digest matches an
expected digest. This is useful for detecting changes, provided the expected
checksum comes from a trusted source. A checksum by itself does not prove who
created or published a file. Use a digital signature or another authenticated
distribution mechanism when publisher authenticity is required.

### Security considerations

- Do not commit passwords, HMAC keys, derived keys, or other secrets.
- Treat salts as public values, but store them with the KDF parameters.
- SHA-256/SHA-512 are general-purpose hashes, not password storage schemes.
- PBKDF2 parameters should be benchmarked and periodically reviewed.
- This educational utility is not a substitute for a security-audited
  cryptographic product or a complete key-management system.

## Unit Tests

Run the test suite:

```bash
python -m unittest -v
```

Tests include SHA-256 and SHA-512 known-answer vectors, a PBKDF2-HMAC-SHA256
known-answer vector, RFC 4231 HMAC-SHA256 test case 1, file hashing,
checksum comparison, and invalid-input handling.
